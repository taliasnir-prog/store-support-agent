# סוכן פניות לקוחות ל-LUMI

מטלה 6 בקורס AIDO (מטמיעי AI) - סוכני AI.

סוכן שקורא פנייה של לקוח בחנות LUMI, משווה אותה למדיניות, בודק בזיכרון אם הלקוח כבר פנה, וכותב טיוטת תשובה. הוא לא שולח כלום: כל טיוטה מחכה לאישור שלי, ומה שדורש החלטה (זיכוי, מוצר פגום, לקוח כועס) מסומן אליי.

הסוכן בנוי ורץ ב-Claude Platform (Managed Agents), עם שני Memory stores ושני טריגרים: הודעה (session לכל פנייה) ותזמון (סבב בוקר).

## הקבצים

| קובץ | מה יש בו |
|---|---|
| [SPEC.md](SPEC.md) | התכנון: מה הסוכן עושה, הכלים, הזיכרון, הבטיחות והבדיקות |
| [Architecture.md](Architecture.md) | זרימת המידע: מאיפה הפנייה מגיעה, מה מפעיל את הסוכן, ולאן הולך הפלט |
| [agent/config.md](agent/config.md) | מסמך הקונפיגורציה של מה שנבנה בפועל: מודל, מאמץ, כלים, סביבה, זיכרון, טריגרים ותוצאות |
| [agent/agent.yaml](agent/agent.yaml) | הגדרת הסוכן כמו שהודבקה ב-Console |
| [agent/system-prompt.md](agent/system-prompt.md) | ההוראות של הסוכן |
| [memory/](memory) | התוכן ההתחלתי של שני ה-Memory stores |
| [tests/test-inquiries.md](tests/test-inquiries.md) | 6 פניות דמה + סבב בוקר, ומה קרה בכל אחת |

כל הבדיקות רצו על פניות דמה בחשבון שלי. אין כאן נתונים של לקוחות אמיתיים. השם LUMI הוא שם בדוי. הסוכן נבנה ונבדק על חנות אמיתית, ולפני הפרסום הוחלפו בריפו שם החנות, שמות המשאבים (למשל `store-policies`) והסטטוס `needs_owner`. ההיגיון, ההגדרות ותוצאות הבדיקות זהים למה שרץ בפועל.
